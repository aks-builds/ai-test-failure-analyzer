# ai-test-failure-analyzer v2.0 — Design Spec

**Date:** 2026-06-20
**Status:** Approved — ready for implementation planning
**Research basis:** Deep research report (106 agents, 24 sources, 7 verified claims — 2026-06-20)

---

## Goal

Evolve ai-test-failure-analyzer from a 7-parser, 8-phase deterministic pipeline into a
full-fledge, self-contained test intelligence platform: 24 parsers covering every major
testing ecosystem, 8 evidence collectors running in parallel, pure-Python ML intelligence
for flaky detection and quality-weighted confidence, CTRF as a canonical output format,
and optional LLM enrichment — all with zero new runtime dependencies.

**Non-goals:** external plugin marketplace, community-installable plugins, graph database,
LLM in the deterministic core.

---

## Research Findings (verified, adversarially checked)

Four claims survive 106-agent adversarial verification from 24 sources:

1. **CTRF is the leading open schema** (high confidence) — native `ai` string field at
   the test-object level; machine-checkable flakiness definition (passed + failed retry);
   pre-1.0, pin to a specific commit in implementation.
   Source: github.com/ctrf-io/ctrf

2. **TF-IDF + Random Forest classifies flaky tests at F1=0.67** (high confidence) across
   7 categories (ID, OD, OD-Vic, OD-Brit, NOD, UD, NDOD) on 1,257 tests / 108 projects.
   Pure static signals — no labeled training data at inference time.
   Source: arXiv 2403.01003 (FlaKat, March 2024)

3. **Agglomerative clustering on Jaccard run-set distances** (medium confidence, unreviewed
   preprint) identifies co-occurring flaky groups without labeled data. Silhouette ≥ 0.6
   as automated threshold. Java-only study; treat as directional.
   Source: arXiv 2504.16777 (April 2025)

4. **ML predictive test selection on code-change signals is production-validated** (medium
   confidence) — CloudBees Smart Tests (formerly Launchable) uses changed files, change
   size, filetypes, and historical pass/fail. Framework-agnostic via CLI.
   Source: help.launchableinc.com (primary docs)

**Killed:** All 6 LLM-in-core RCA claims were refuted (0-3 or 1-2 votes). LLM-based
autonomous root cause analysis is not production-viable at the level claimed in
benchmarks. Deterministic + optional LLM enrichment is the right architecture.

## Section 1 — Architecture

### 1.1 Structural Changes (3)

internal registries and a parallel collector model. All implementations ship inside

### 2.3 Special Cases

**Go test JSON:** Outputs NDJSON (one JSON object per line). `can_parse()` reads the
first line and checks for `{"Action":`. `parse()` streams lines, accumulates `output`
lines per test, emits `NormalizedFailure` on each `"Action":"fail"` event. No full-file
buffering.

**Gatling simulation.log:** TSV format. Columns: `type`, `start`, `end`, `status`,
`message`. `REQUEST` lines with `status=KO` become failures. `USER` lines provide
scenario context. Pure `str.split('\t')`.

**CTRF as canonical input:** Any team using CTRF reporters (official reporters exist for
Playwright, Jest, Cypress, Vitest, pytest, Newman, k6, Robot Framework, RSpec, Go test)
gets zero-friction compatibility via `CTRFJsonParser` — one parser path for all.

## Section 3 — Evidence Expansion

### 3.1 EvidenceCollector ABC

```python
class EvidenceCollector(ABC):
    name: str
    tier: Literal["tier1", "tier2"]

    @classmethod
    def is_available(cls, workspace: Path, profile: WorkspaceProfile) -> bool:
        """Fast existence check only. No I/O beyond os.path calls."""

    @classmethod
    def collect(cls, workspace: Path, profile: WorkspaceProfile) -> EvidenceBundle:
        """Returns populated or empty bundle. Never raises — catches all exceptions."""
```

`EvidenceRegistry.collect_all()` calls `is_available()` first, logs active/skipped
collectors, then runs all available collectors concurrently. Each collector has a 30s
timeout (configurable via `.atfa/config.json`). Timeout or exception → `EvidenceBundle.empty(name)`.

### 3.2 Existing Collectors (refactored, behaviour unchanged)

| Collector | Tier | Available when |
|---|---|---|
| `GitCollector` | Tier-1 | `.git/` exists |
| `LogCollector` | Tier-1 | `*.log` or `logs/` found in workspace |
| `ConfigCollector` | Tier-1 | `.env`, `docker-compose.*`, or `*.config.*` found |

### 3.3 New Collectors (5)

#### `DepDiffCollector` — Tier-1

Detects changes to dependency manifests between `HEAD` and `HEAD~10` (depth configurable).

Scanned manifests: `package.json`, `package-lock.json`, `requirements.txt`,
`pyproject.toml`, `go.mod`, `Gemfile`, `Gemfile.lock`, `Cargo.toml`, `pom.xml`,
`build.gradle`.

For each changed manifest: extracts added/removed/bumped packages via `git diff HEAD~N -- <file>`,
parsed with stdlib string matching (no semver library). Emits `DepChange(package, from, to, file, commit)`.

Available when: `.git/` exists AND any manifest file found. Graceful on empty diff.

#### `ContractDiffCollector` — Tier-1

Detects breaking changes in committed OpenAPI/Swagger specs or Pact snapshots.

Sniffs for: `openapi.yaml`, `openapi.json`, `swagger.yaml`, `swagger.json`,
`**/openapi/**`, `pact/`, `pacts/`. Diffs against `HEAD~1` via `git show HEAD~1:<path>`
(stdlib subprocess). Parses diff for: removed paths, changed response schemas, changed
status codes, removed required fields.

Available when: any OpenAPI/Pact file detected. If found but unchanged → empty bundle
(`"no contract changes detected"`). If not found → silently skipped.

#### `CIContextCollector` — Tier-2

Reads CI environment variables; normalises across providers:

| Provider | Detection | PR number | Changed files |
|---|---|---|---|
| GitHub Actions | `GITHUB_ACTIONS=true` | `GITHUB_PR_NUMBER` | GitHub API (if `GITHUB_TOKEN` set) |
| GitLab CI | `GITLAB_CI=true` | `CI_MERGE_REQUEST_IID` | `CI_MERGE_REQUEST_DIFF_BASE_SHA` |
| CircleCI | `CIRCLECI=true` | `CIRCLE_PULL_REQUEST` | — |
| Jenkins | `JENKINS_URL` set | `ghprbPullId` | — |

On GitHub Actions with `GITHUB_TOKEN`: fetches PR file list via single `urllib.request`
call. Changed files surface as Tier-2 evidence correlated against failing test paths.

Available when: any CI env var detected. On local runs → silently skipped.

#### `OtelCollector` — Tier-1 (when available)

Reads OpenTelemetry trace exports. Primary mode: static export files
(`traces.json`, `otel-traces.json`, `*.otlp.json`). Secondary mode: HTTP endpoint
configured via `ATFA_OTEL_ENDPOINT` (5s timeout, skipped on failure).

Correlates failing test names against span names by URL substring match.
Extracts: `span.status`, `db.statement`, `error.message`, service name, duration.

Graceful degradation tiers:
1. Export file found + parseable → full span correlation
2. Export file found but empty → `"no spans in trace export"`
3. Endpoint configured, HTTP succeeds → span correlation
4. Endpoint configured, HTTP fails → warning + empty bundle
5. Nothing configured → silently skipped, zero impact on analysis

#### `FlakyHistoryCollector` — Tier-2

Reads `.atfa/history.json` — a local run-history file the tool writes after each analysis
(capped at 50 runs, stdlib `json`). Computes per-failure Jaccard distances across run-sets
to surface intermittently failing tests.

Available when: `.atfa/history.json` exists. On first run → skipped; history file
created at analysis end.

### 3.4 EvidenceGraph

Pure Python adjacency list — no graph library.

```python
@dataclass
class EvidenceNode:
    id: str
    type: str     # "failure"|"commit"|"log_line"|"dep_change"|"span"|"config"|"contract"
    ref: str      # file:line, commit hash, log line number, span ID, etc.
    weight: float # tier1=2.0, tier2=1.0, noise=0.0
    excerpt: str

@dataclass
class EvidenceEdge:
    src: str; dst: str
    relation: str  # "caused_by"|"co_occurs_with"|"related_to"|"contradicts"
    weight: float

class EvidenceGraph:
    nodes: dict[str, EvidenceNode]
    edges: list[EvidenceEdge]

    def strongest_chain(self, failure_id: str) -> list[EvidenceNode]:
        """BFS from failure node, accumulates edge weights, returns highest-weight path."""

    def total_weight(self, failure_id: str) -> float:
        """Sum of weights on all outgoing edges from a failure node."""

    def nodes_for_cluster(self, cluster_id: str) -> list[EvidenceNode]:
        """All evidence nodes linked to any failure in a cluster."""
```

Each evidence collector contributes nodes. The correlator draws edges. Hypothesis
formation traverses `strongest_chain()` — pure Python BFS with weight accumulation.

## Section 4 — Intelligence Layer

All intelligence is pure Python stdlib. No scikit-learn, no numpy, no external ML deps.

### 4.1 Phase 2.5 — Flaky Test Detection (`analyzer/intelligence/flaky_detector.py`)

Runs after Phase 1, before evidence collection. Annotates each `NormalizedFailure`
in-place with `flakiness_score` (0.0–1.0) and `flakiness_category`.

**Three combined signals:**

**Signal 1 — TF-IDF cosine similarity on error messages**

Pairs of tests with cosine similarity ≥ 0.85 are flagged as co-flaky candidates.
Score contribution: `+0.3` per high-similarity neighbour, capped at `+0.6`.

```python
# Pure Python — math.log + collections.Counter only
def _tfidf(docs: list[str]) -> list[dict[str, float]]: ...
def cosine_similarity(v1: dict, v2: dict) -> float: ...
```

**Signal 2 — FlaKat 7-category classification**

Keyword + pattern matching on `error_message + error_stack`:

| Category | Key signals |
|---|---|
| `ID` (Implementation-Dependent) | `timeout`, `stale element`, `detached`, `intercept`, `element not found` |
| `OD` (Order-Dependent) | `already exists`, `duplicate key`, `setup`, `teardown`, `beforeAll` |
| `NOD` (Non-Deterministic) | `random`, `concurrent`, `race condition`, `deadlock`, `async` |
| `UD` (Unknown-Dependency) | `ECONNREFUSED`, `ENOTFOUND`, `network`, `DNS`, `socket hang up` |
| `NDOD` | `flaky` literal in test name/error + NOD signals |
| `OD-Vic` / `OD-Brit` | Test name contains `setup`/`teardown` + OD signals |

Score contribution: `+0.1` per matched keyword signal, capped at `+0.4`.

**Signal 3 — Jaccard run-history distance** (requires `FlakyHistoryCollector` data)

```python
def jaccard_distance(set_a: set, set_b: set) -> float:
    if not set_a and not set_b:
        return 0.0
    return 1 - len(set_a & set_b) / len(set_a | set_b)
```

Tests that fail in different subsets of runs (high distance = intermittent) contribute
`+0.3` to score.

**Final score:** sum of three signals, capped at 1.0. Score ≥ 0.5 → test labelled
"probable flake" in report; `flakiness_category` set. Status field is not changed —
the flakiness label is advisory, not a verdict.

### 4.2 Phase 6 Upgrade — EvidenceGraph Clusterer (`analyzer/intelligence/clusterer.py`)

Replaces signature-tuple grouping with Jaccard-distance agglomerative clustering.

**Composite distance function between two failures:**

```python
def failure_distance(a, b, graph) -> float:
    d = 1.0
    # Shared git commits → -0.4 (strongest signal)
    if commits_a(graph, a) & commits_b(graph, b):
        d -= 0.4
    # Same HTTP status class → -0.2
    if same_status_class(a, b):
        d -= 0.2
    # Error message cosine similarity ≥ 0.85 → -0.2
    if cosine_sim(a.error_message, b.error_message) >= 0.85:
        d -= 0.2
    # Same flakiness category → -0.1 (co-flaky, weak signal)
    if a.flakiness_category and a.flakiness_category == b.flakiness_category:
        d -= 0.1
    return max(0.0, d)
```

Agglomerative merge: build O(n²) distance matrix, merge closest pair below threshold
0.4, repeat until no pairs remain. Hard cap: 300 failures max (configurable in
`.atfa/config.json`).

### 4.3 Phase 7 Upgrade — Quality-Weighted Scorer (`analyzer/intelligence/scorer.py`)

Replaces source-count formula:

```python
def score_cluster(cluster_id, graph, failures) -> tuple[int, str]:
    raw_weight = graph.total_weight(cluster_id)        # Tier-1=2.0, Tier-2=1.0
    source_types = {n.type for n in graph.nodes_for_cluster(cluster_id)}
    corroboration = min(len(source_types) * 5, 20)     # +5 per independent source type
    flaky_penalty = min(flaky_count(failures) * 8, 20) # -8 per probable flake
    contradiction_penalty = contradiction_count(graph) * 15
    raw = int(raw_weight * 15) + corroboration - flaky_penalty - contradiction_penalty
    # Hard caps
    if tier1_count(graph, cluster_id) == 0:
        raw = min(raw, 40)
    elif source_types <= {"test_output"}:
        raw = min(raw, 55)
    return max(10, min(98, raw)), build_justification(source_types, ...)
```

Key differences from current:
- Evidence **quality** matters (Tier-1 weight 2.0 vs Tier-2 weight 1.0)
- Flaky tests actively **penalise** confidence rather than contributing to it
- Contradicting evidence reduces score
- Hard caps are evidence-based, not arbitrary thresholds

### 4.4 Phase 9 — Optional LLM Enrichment (`analyzer/enricher.py`)

## Section 5 — CTRF Output, Reliability & Delivery

### 5.1 CTRF Output (`analyzer/render/ctrf.py`)

New CLI flags: `--out results.ctrf.json` (auto-detected by extension), `--format ctrf`.

CTRF `ai` field (§9.11): one-line summary of top hypothesis for each test.
CTRF `extra` object: `hypothesis_confidence`, `hypothesis_title`, `flakiness_score`,
`flakiness_category`, `evidence_sources`, `buggy_location`.

### 5.2 Result Caching

Location: `.atfa/cache/<sha1>.json`

Cache key = `SHA1(git_HEAD + env_mtime + package_json_mtime + results_mtime + results_size)`.
Computing key: < 10ms. Cache hit: all phases emit `"status": "cached"`, result returned
in < 100ms. Expiry: 24h mtime check. Override: `--no-cache`.

### 5.3 Parallel Evidence Collection

```python
# Phase 5.5 — replaces sequential phases 3-5
from concurrent.futures import ThreadPoolExecutor, TimeoutError

def collect_all_evidence(workspace, profile, timeout=30):
    available = [c for c in EVIDENCE_REGISTRY if c.is_available(workspace, profile)]
    results = {}
    with ThreadPoolExecutor(max_workers=min(len(available), 6)) as pool:
        futures = {pool.submit(c.collect, workspace, profile): c for c in available}
        for future, collector in futures.items():
            try:
                results[collector.name] = future.result(timeout=timeout)
            except (TimeoutError, Exception) as exc:
                emit_warning(f"{collector.name} skipped: {exc}")
                results[collector.name] = EvidenceBundle.empty(collector.name)
    return results
```

Expected wall-clock improvement: ~4s sequential → ~1.5s parallel on a typical repo.

### 5.4 Run History Write-back

After every successful analysis: append to `.atfa/history.json` (capped at 50 runs,
stdlib `json`). `.atfa/` gitignored by default; tool writes `.gitignore` entry on
first run. Teams may commit `.atfa/history.json` for shared flaky history.

### 5.5 `--watch` Mode

`ai-analyze watch results.json` — polls mtime every 2s (stdlib `time.sleep` + `os.stat`).
On change: clears terminal, re-runs full analysis. Exits on Ctrl+C. No watchdog dep.

### 5.6 Structured JSON Output

`--format json` emits `AnalysisResult.to_dict()`. New top-level keys in v2:
`"ctrf_summary"`, `"flaky_tests"` (failures with `flakiness_score >= 0.5`),
`"phase_timings"`.

```bash
ai-analyze analyze results.json --format json | jq '.hypotheses[0].confidence'
# 87
```
